Two minutes · three commands

Verify it yourself in two minutes

You do not have to take the site’s word for what the analyser finds. Download the released jar, check the checksum the release publishes, and run it against a fixture that ships in the repository. The console output below is what this build prints today — if yours differs, the last section says why.

  1. Download it and check the checksum

    Every release publishes SHA256SUMS.txt next to the jar. Verify before you run — the point of a checksum is that you do not have to trust the download.

    bash · linux
    HOST=https://github.com/RohithV16/aem-code-analyser
curl -LO "$HOST/releases/latest/download/aem-analyser-cli.jar"
curl -LO "$HOST/releases/latest/download/SHA256SUMS.txt"
sha256sum -c SHA256SUMS.txt
    bash · macOS (no sha256sum)
    shasum -a 256 -c SHA256SUMS.txt

    Both print aem-analyser-cli.jar: OK. Anything else — a missing file, a FAILED line — means the download did not match the release; stop there.

  2. Run it against the fixture

    validation/reactor is a small Maven reactor committed to the repository specifically to be analysed: four modules, one duplicated servlet path, two orphaned OSGi configurations and a handful of parity findings. Nothing else is needed — no AEM instance, no credentials, no network.

    bash
    git clone https://github.com/RohithV16/aem-code-analyser
cd aem-code-analyser
java -jar ~/aem-analyser-cli.jar validation/reactor --no-html --no-color

    --no-html keeps the run read-only — it prints the report instead of also writing a dashboard. Drop it to get target/aem-analyser/aem-analyser-report.html.

  3. Compare the console output

    The run must start and end with this, and exit 1 — the fixture has errors:

    console output · head

    The duration and the project root are machine-specific; the counts, the verdict and the hotspot order are not. Ten findings, four of them errors, exit code 1.

The fixture versus a real project

Ten findings is a fixture, not a benchmark. The reference project this site was built against is a production AEM reactor that produced 36 findings — 7 errors, 28 warnings, 1 info — and therefore also exited 1. That is the difference the tool is for: the fixture proves the install works, a real reactor is where the cross-module findings appear.

The sample report is the same 10-finding validation/reactor fixture, not a customer project; it is there to show the dashboard, not to claim a result.

If your numbers differ

  • Different JDK. The jar targets Java 21. A newer JDK is fine; a JRE older than 21 fails to start, and the error names the version.
  • A different checkout. The fixture counts depend on the files present — a filtered clone, a dirty working tree or a missing submodule changes the totals. Use a clean clone of the tag you downloaded.
  • A different release. Rules are added between releases. The counts above are from the current release; --list-rules prints the catalogue your jar actually carries, and --version prints the version.
