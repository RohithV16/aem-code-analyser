CLI reference

Everything the analyser accepts, in one place. Defaults are what you get when you pass nothing — which is the intended way to start.

Usage

bash
java -jar aem-analyser-cli.jar [options] [project-root]

Output formats

Formats combine: pass a comma-separated list to --format. Only CONSOLE and TEXT write to stdout; every other format is a file under --output (default target/aem-analyser).

FormatFileConsumer
CONSOLEstdout (plugin: aem-analyser-report.txt)Terminal and build log
TEXTaem-analyser.txt One file:line:col: E AEM-RULE message line per finding — vim :cfile/:make, Emacs compilation-mode, VS Code's $gcc problem matcher, grep. Also echoed to stdout.
JSONaem-analyser-report.json Neutral machine-readable document: schemaVersion, tool version, per-severity counts, every finding with its fingerprint and rule metadata. Dashboards, bespoke gates, MCP/LLM tools.
HTMLaem-analyser-report.htmlPeople: a standalone dashboard
SARIFaem-analyser.sarifGitHub code scanning, Azure DevOps
SONARsonar-aem-analyser-report.jsonSonarQube external issues
GITHUBgithub-annotations.txt::error / ::warning lines — cat the file in the step
GITLABgitlab-code-quality.jsonGitLab code quality artefact
AZUREazure-pipelines.log##vso logging commands — cat the file in the step

Exit codes

CodeMeaning
0 Analysis completed and the gate passed. --fail-on NONE always exits 0 unless a coverage or duplication threshold trips.
1 The gate failed — any ERROR-severity finding by default, anything at or above --fail-on, --fail-on-warning, or a --min-coverage / --max-duplication / --max-warnings breach.
2 The analysis could not run. Not a verdict on the code.

Exit codes are a CLI contract. Through Maven, both a failed gate and a failed analysis surface as a build failure, so the pipeline sees one non-zero exit.

Configuration file

.aem-analyser.yml in the project root, or a path given with --config. Every key is optional.

.aem-analyser.yml
rules:
  AEM-DEAD-003B:
    enabled: false
  AEM-SEC-001:
    severity: ERROR
allowlists:
  services:
    - com.example.LegacyService
  configPaths:
    - ui.config/**/config.local/**
  • rules.<ID>.enabled — turn a rule off without touching source.
  • rules.<ID>.severity — raise or lower a rule’s severity for this project.
  • allowlists.services — classes that are never reported as unused services.
  • allowlists.configPaths — configuration globs the dead-configuration rules ignore.
  • schemaVersion — configuration format version (currently 1).

Baseline

A baseline freezes the findings that exist today, so a gate can fail on new ones only. Totals and exit codes count active findings; accepted ones are listed separately in the dashboard’s Run Health tab.

bash
java -jar aem-analyser-cli.jar --update-baseline
java -jar aem-analyser-cli.jar --baseline .aem-analyser-baseline.json
java -jar aem-analyser-cli.jar --baseline .aem-analyser-baseline.json --baseline-report

--baseline-report keeps suppressed findings visible at INFO, which is what you want while paying a baseline down.

Inline suppression

The next line is skipped for the named rule. Unknown rule ids are ignored, so a typo silences nothing.

java
// aem-analyser-disable-next-line AEM-DEAD-001
html · HTL and XML
<!-- aem-analyser-disable-next-line AEM-SEC-001 -->

Two ids have no suppression hook because they are not produced by a rule evaluator: AEM-DUP-010 comes from the PMD CPD scan, and AEM-QUAL-006 is retired — AEM-QUAL-004 now owns that check.

Maven plugin

Coordinates: io.github.rohithv16:aem-analyser-maven-plugin. Goals report and check.

ParameterDefaultDescription
formatsSARIF,SONARComma-separated formats for report; check defaults to CONSOLE.
outputFile${project.build.directory}Output directory, or the file itself when exactly one format is configured.
failOnunsetSeverity threshold for the check goal: NONE, ERROR, WARNING or INFO. NONE is report-only — the severity gates are skipped and only minCoverage, maxDuplication and maxWarnings can still fail the build. Any other value is rejected. Unset means any ERROR fails.
failOnErrortrueFail when at least one ERROR finding exists (the default gate).
failOnWarningfalseAlso fail when WARNING findings exist.
projectRootreactor rootAnalyse a different directory.
enableSonartrueEmbedded SonarJava analysis.
configFile.aem-analyser.ymlProject configuration file.

These are the six you are likely to touch; the full parameter list (threads, baselines, Git diffing, history, Sonar rules, coverage gates) mirrors the CLI flags and is documented in the README.

The same values work from the command line:

bash
mvn -B -ntp io.github.rohithv16:aem-analyser-maven-plugin:1.0.10:report \
  -Daem-analyser.formats=SARIF,HTML \
  -Daem-analyser.outputFile=target/aem-analyser

What gets scanned

One pass over the reactor reads Java sources, HTL and JSP templates, OSGi configuration (.cfg.json, .config, sling:OsgiConfig), client library definitions, package metadata and content package filters. Files larger than --max-file-size are skipped and reported as diagnostics rather than silently dropped.

Skipped or partially parsed files appear in the dashboard’s Run Health tab — a clean result on a run with diagnostics is not the same as a clean result on a run without them.
