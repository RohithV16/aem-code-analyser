AEM-CLOUD-003 UnmappedSubserviceUser

Java call to getServiceResourceResolver() has no matching ServiceUserMapperImpl.amended mapping or system user definition.

ERROR · 25 min fix · Code smell · AEM as a Cloud Service

Java call to getServiceResourceResolver() has no matching ServiceUserMapperImpl.amended mapping or system user definition.

Why it matters

getServiceResourceResolver only works when a ServiceUserMapper mapping exists for the bundle's subservice and the service user exists in the repository. Without the mapping the call fails at runtime with a LoginException, and the feature only breaks on the environment where the config is missing.

How to fix it

Declare the service user through repoinit and add the mapping in a configuration file for the ServiceUserMapperImpl.amended factory, then grant the ACLs the feature needs.

text · before
// Java asks for subservice "search" but no mapping ships
resolverFactory.getServiceResourceResolver(
        Map.of(ResourceResolverFactory.SUBSERVICE, "search"));
text · after
ui.config/.../config/org.apache.sling.serviceusermapping.impl.ServiceUserMapperImpl.amended-acme.cfg.json
  { "user.mapping": [ "com.acme.core:search=acme-search-service" ] }

ui.config/.../config/org.apache.sling.jcr.repoinit.RepositoryInitializer-acme.cfg.json
  { "scripts": [ "create service user acme-search-service with path /home/users/acme" ] }
