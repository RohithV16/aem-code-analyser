AEM-CLOUD-006 BrokenDispatcherConfig

Dispatcher configuration has an unresolved include, a duplicate ServerName, a vhost without DocumentRoot or a legacy dispatcher.any.

WARNING · 20 min fix · Code smell · AEM as a Cloud Service

Dispatcher configuration has an unresolved include, a duplicate ServerName, a vhost without DocumentRoot or a legacy dispatcher.any.

Why it matters

The dispatcher is validated only when Cloud Manager deploys, so a broken include, a duplicated ServerName, a virtual host with no DocumentRoot or a monolithic dispatcher.any turns into a failed pipeline rather than a failed build. The same defects are also the usual cause of "works in dev, 404 in prod": the vhost never loads, or two vhosts answer for one host name and whichever loads last wins.

How to fix it

Create the missing include target or fix the path, give every virtual host its own ServerName, add DocumentRoot "${DOCROOT"} to each block, and split a legacy monolithic dispatcher.any into conf.dispatcher.d (farms, filters, cache, renders, virtualhosts) plus conf.d (vhosts, rewrites, variables).

text · before
# dispatcher/src/conf.d/available_vhosts/acme.vhost
Include conf.d/includes/cache-rules.conf   # no such file
<VirtualHost *:80>
    ServerName "www.acme.com"
</VirtualHost>
text · after
# dispatcher/src/conf.d/available_vhosts/acme.vhost
Include conf.d/includes/cache.conf
<VirtualHost *:80>
    ServerName "www.acme.com"
    DocumentRoot "${DOCROOT}"
</VirtualHost>
