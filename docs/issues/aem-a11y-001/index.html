AEM-A11Y-001 ImageWithoutAlt

HTL img element has no alt attribute or data-sly-attribute.alt fallback (WCAG 1.1.1).

WARNING · 10 min fix · Bug · Accessibility

HTL img element has no alt attribute or data-sly-attribute.alt fallback (WCAG 1.1.1).

Why it matters

WCAG 1.1.1 requires a text alternative for every image that conveys meaning. Sightly renders an <img> exactly as written, so a missing alt reaches the page even though every other output expression is escaped. Screen readers then announce the file name or skip the image entirely, and tools such as axe can only find it after the page is rendered and deployed.

How to fix it

Add alt with a short description, bind it with data-sly-attribute.alt when it comes from the component, or use an empty alt="" for a purely decorative image. A dynamic expression counts as present: the value is resolved per request.

html · before
<!-- components/hero/hero.html -->
<img src="${model.image}" class="hero__image">
html · after
<!-- components/hero/hero.html -->
<img src="${model.image}" class="hero__image" alt="${model.imageAlt}">

<!-- decorative divider: empty alt, not a missing one -->
<img src="/etc.clientlibs/acme/divider.svg" alt="">
