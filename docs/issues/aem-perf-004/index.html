AEM-PERF-004 UnboundedQuery

JCR/Oak query has no limit and may scan an unbounded result set.

WARNING · 20 min fix · Code smell · Performance

JCR/Oak query has no limit and may scan an unbounded result set.

Why it matters

An unbounded query result can be enormous on a content repository that grows daily. It is the usual cause of a slow component that only shows up in production.

How to fix it

Bound the result set with p.limit (or LIMIT in JCR-SQL2) and paginate with p.offset. Report the total separately with p.guessTotal rather than materialising every hit.

java · before
Map<String, String> params = Map.of(
        "path", "/content/acme",
        "type", "cq:Page",
        "property", "jcr:content/sling:resourceType");
java · after
Map<String, String> params = new HashMap<>();
params.put("path", "/content/acme");
params.put("type", "cq:Page");
params.put("p.limit", "50");
params.put("p.offset", String.valueOf(page * 50));
params.put("p.guessTotal", "1000");
