AEM-QUAL-002 ProviderTypeImplementation

Custom code implements or extends @ProviderType product interface (CQBP-84).

ERROR · 30 min fix · Bug · Quality and Cloud Manager parity

Custom code implements or extends @ProviderType product interface (CQBP-84).

Why it matters

Implementing or extending a @ProviderType interface ties your bundle to product internals that AEM as a Cloud Service upgrades without notice; CQBP-84 fails the build for exactly this reason. Provider types are contracts you consume, not implement.

How to fix it

Depend on the interface and delegate to it instead of implementing it. When you need to decorate behaviour, wrap the product object or move the logic into your own service that takes the provider type as a dependency.

java · before
public class CachedPage implements com.day.cq.wcm.api.Page {
    // re-implements a provider type: breaks on upgrade
}
java · after
@Component(service = PageTitleService.class)
public class PageTitleService {

    @Reference
    private ResourceResolverFactory resolverFactory;

    public String titleFor(String path) throws LoginException {
        Map<String, Object> auth =
                Map.of(ResourceResolverFactory.SUBSERVICE, "title-read");
        try (ResourceResolver resolver =
                     resolverFactory.getServiceResourceResolver(auth)) {
            PageManager pageManager = resolver.adaptTo(PageManager.class);
            Page page = pageManager == null ? null : pageManager.getPage(path);
            return page == null ? "" : page.getTitle();
        }
    }
}
