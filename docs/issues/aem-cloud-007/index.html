AEM-CLOUD-007 OverlappingContentPackageFilter

A content-package filter root is shared across modules, uses replace on a shared root, or points at a platform path.

WARNING · 20 min fix · Code smell · AEM as a Cloud Service

A content-package filter root is shared across modules, uses replace on a shared root, or points at a platform path.

Why it matters

Filter roots decide which repository paths a package installs. When two modules filter the same root, the package installed last wins, so content from the other package silently disappears in the deployed environment — and the build, the package manager and both modules' own tests all still pass. mode="replace" on a shared root makes that deletion explicit. A root at /apps, /content/dam or under /libs ships content the project does not own.

How to fix it

Give each content module a disjoint root under the project namespace. Where a root genuinely must be shared, use mode="merge" and include only the paths the module owns instead of the platform root itself.

json · before
<!-- ui.apps/src/main/content/META-INF/vault/filter.xml -->
<workspaceFilter version="1.0">
    <filter root="/content/acme" mode="replace"/>
</workspaceFilter>

<!-- ui.content/src/main/content/META-INF/vault/filter.xml -->
<workspaceFilter version="1.0">
    <filter root="/content/acme" mode="merge"/>
</workspaceFilter>
json · after
<!-- ui.apps/src/main/content/META-INF/vault/filter.xml -->
<workspaceFilter version="1.0">
    <filter root="/apps/acme/components"/>
</workspaceFilter>

<!-- ui.content/src/main/content/META-INF/vault/filter.xml -->
<workspaceFilter version="1.0">
    <filter root="/content/acme" mode="merge"/>
</workspaceFilter>
