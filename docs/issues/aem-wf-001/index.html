AEM-WF-001 UnresolvedWorkflowReference

Workflow launcher points at a model, or a PROCESS step at a class, that the project does not ship.

WARNING · 15 min fix · Bug · Workflow integrity

Workflow launcher points at a model, or a PROCESS step at a class, that the project does not ship.

Why it matters

A workflow launcher references its model by path and a PROCESS step references its class by name; both are plain strings in .content.xml. Rename the model or move the class and nothing complains at deploy time - the launcher simply never starts, and the workflow that "stopped running weeks ago" is the first symptom. Cloud Manager and the AEM Analyzer do not inspect workflow content at all.

How to fix it

Point cq:workflowModel at a model the project ships (or at an existing out-of-the-box model), and update the PROCESS step to the class that now implements it. Grep the model path and the class name across the package before renaming either.

xml · before
<!-- conf/global/settings/workflow/launcher/acme-publish/.content.xml -->
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          jcr:primaryType="cq:WorkflowLauncher"
          cq:workflowModel="/var/workflow/models/acme-missing"
          glob="/content/acme/.*/jcr:content"/>

<!-- conf/global/settings/workflow/models/acme-publish/.content.xml -->
<jcr:root jcr:primaryType="cq:WorkflowModel">
    <node0 jcr:primaryType="cq:WorkflowNode" type="PROCESS"
           process="com.acme.steps.Gone"/>
</jcr:root>
xml · after
<!-- launcher points at the model that exists -->
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          jcr:primaryType="cq:WorkflowLauncher"
          cq:workflowModel="/var/workflow/models/acme-publish"
          glob="/content/acme/.*/jcr:content"/>

<!-- step names a class the bundle declares -->
<jcr:root jcr:primaryType="cq:WorkflowModel">
    <node0 jcr:primaryType="cq:WorkflowNode" type="PROCESS"
           process="com.acme.steps.PublishStep"/>
</jcr:root>
