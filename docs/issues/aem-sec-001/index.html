AEM-SEC-001 UnsafeHtlContextBypass

HTL expression uses @ context='unsafe' bypassing XSS protection.

ERROR · 20 min fix · Vulnerability · Security

HTL expression uses @ context='unsafe' bypassing XSS protection.

Why it matters

context='unsafe' switches off HTL's contextual escaping, and the expression is written into the page verbatim. With any author-controlled or request-derived value that is a stored XSS hole (CWE-79) on a publish tier.

How to fix it

Drop unsafe and let HTL pick the context from the surrounding markup. When you really must emit markup, use context='html' and pass it through a sanitiser such as the Granite XSS API.

html · before
<div class="footer">${model.footerHtml @ context='unsafe'}</div>
html · after
<div class="footer">${model.footerHtml @ context='html'}</div>
