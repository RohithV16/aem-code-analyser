AEM-DEAD-003A UnusedOsgiService

OSGi Service has zero injections across bundles and is not a system entry point.

WARNING · 30 min fix · Bug · Dead code

OSGi Service has zero injections across bundles and is not a system entry point.

Why it matters

A registered OSGi service that nothing injects and that no framework calls is code the build still compiles, tests and deploys. On AEM as a Cloud Service it also keeps its dependencies and configuration alive.

How to fix it

Inject the service where it was meant to be used, drop the service = ... registration so the class becomes a plain component, or export its package when it is a deliberate API for other bundles.

java · before
@Component(service = LegacyImportService.class)
public class LegacyImportService {
    // no @Reference to this type anywhere in the reactor
}
java · after
@Component
public class ImportJobConsumer implements JobConsumer {
    // used through the Sling Job API, not through an injected reference
}
