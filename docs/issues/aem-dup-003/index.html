AEM-DUP-003 DuplicateSlingModel

Multiple Sling Models bind to the exact same resourceType and adapter interface without condition.

WARNING · 15 min fix · Code smell · Duplication

Multiple Sling Models bind to the exact same resourceType and adapter interface without condition.

Why it matters

Two Sling Models bound to the same resourceType and adaptable means HTL can resolve either one; the winner is undefined. Exported JSON then differs depending on which model the model factory picked.

How to fix it

Keep one model per resource type, or separate them by selector, resource type or a condition, and let HTL choose explicitly.

java · before
@Model(adaptables = Resource.class, resourceType = "acme/components/card")
public class CardModel { }

@Model(adaptables = Resource.class, resourceType = "acme/components/card")
public class CardViewModel { }
java · after
@Model(adaptables = Resource.class, resourceType = "acme/components/card",
       defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL)
public class CardModel { }

@Model(adaptables = Resource.class, resourceType = "acme/components/card/view")
public class CardViewModel { }
