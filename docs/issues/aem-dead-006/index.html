AEM-DEAD-006 MissingTranslationKey

Translation key used by a template or model has no entry in the baseline (en) dictionary.

WARNING · 20 min fix · Bug · Dead code

Translation key used by a template or model has no entry in the baseline (en) dictionary.

Why it matters

AEM prints the raw key when ${'key' @ i18n} has no dictionary entry, so a missing translation ships to production as visible text. The build and the bundle both pass, and the only signal is a customer reading "checkout.title" on the page. Keeping every locale in step by hand also guarantees that the en dictionary silently drifts behind the templates.

How to fix it

Add the key to the baseline en.json under the project's i18n folder, then add the translated value to each locale file. Use one spelling of the key in templates and models; the dictionary lookup is exact and case-sensitive.

html · before
<!-- components/checkout/checkout.html -->
<h1>${'checkout.title' @ i18n}</h1>

<!-- ui.apps/.../i18n/en.json -->
{
  "checkout.cart": "Your cart"
}
html · after
<!-- components/checkout/checkout.html -->
<h1>${'checkout.title' @ i18n}</h1>

<!-- ui.apps/.../i18n/en.json -->
{
  "checkout.cart": "Your cart",
  "checkout.title": "Checkout"
}
