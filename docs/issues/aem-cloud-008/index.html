AEM-CLOUD-008 ImmutablePathWrite

Java writes to /apps or /libs at runtime, an area AEM as a Cloud Service keeps immutable.

ERROR · 15 min fix · Bug · AEM as a Cloud Service

Java writes to /apps or /libs at runtime, an area AEM as a Cloud Service keeps immutable.

Why it matters

In AEM as a Cloud Service the repository structure is decided at build time by the packages a deployment installs; /apps and /libs are immutable and "any attempt to change an immutable area at runtime fails". Code that wrote configuration, labels or counters into /apps for years on 6.5 keeps compiling and deploying, then throws AccessDeniedException (or silently drops the write) at the first request.

How to fix it

Move the node into the content package so it is installed with the release, or keep runtime state under a mutable path (/var, /conf, /content) that the service user is allowed to modify.

java · before
ValueMap config =
    resolver.getResource("/apps/acme/config").adaptTo(ModifiableValueMap.class);
config.put("lastRun", System.currentTimeMillis());
java · after
// ui.content/src/main/content/jcr_root/apps/acme/config/.content.xml
<jcr:root xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          jcr:primaryType="sling:Folder"/>

// Java: runtime state belongs under a mutable path
ValueMap state =
    resolver.getResource("/var/acme/config").adaptTo(ModifiableValueMap.class);
state.put("lastRun", System.currentTimeMillis());
