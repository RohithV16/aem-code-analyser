AEM-PERF-003 OakQueryTraversalRisk

JCR-SQL2 or XPath query lacks path or nodetype restriction, causing Oak traversal errors.

WARNING · 25 min fix · Code smell · Performance

JCR-SQL2 or XPath query lacks path or nodetype restriction, causing Oak traversal errors.

Why it matters

A JCR-SQL2 or XPath query with no path or node type restriction forces Oak to walk every index it has. At scale that is the difference between a millisecond lookup and a traversal warning in the Cloud Service logs.

How to fix it

Add a path= or type= constraint (or ISDESCENDANTNODE) so Oak can use a property index, and confirm the index exists.

sql2 · before
SELECT * FROM [nt:base] AS s
WHERE [sling:resourceType] = 'acme/components/card'
sql2 · after
SELECT * FROM [nt:base] AS s
WHERE ISDESCENDANTNODE(s, '/content/acme') AND [sling:resourceType] = 'acme/components/card'
