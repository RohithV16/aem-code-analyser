AEM-CLOUD-010 LegacyReplicationConfiguration

Replication agent content, replication OSGi configuration or a custom transport handler that AEM as a Cloud Service cannot honour.

WARNING · 15 min fix · Bug · AEM as a Cloud Service

Replication agent content, replication OSGi configuration or a custom transport handler that AEM as a Cloud Service cannot honour.

Why it matters

Cloud publishing does not use replication agents. Content is distributed through Sling Content Distribution to an Adobe-hosted pipeline service, so an agent shipped under /etc/replication, an OSGi config for com.day.cq.replication.impl.* or a Sling distribution agent, and a custom TransportHandler configure nothing at all. Unlike every other Cloud difference this one produces no error: the agent reports idle, the activation request "succeeds", and the published page never appears.

How to fix it

Delete the agent content and the transport configuration from the package, and replace a custom TransportHandler / ContentBuilder / ReplicationPreprocessor with the standard replication API or a workflow step that Cloud runs.

xml · before
<!-- ui.apps/src/main/content/jcr_root/etc/replication/agents.author/publish/.content.xml -->
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          jcr:primaryType="cq:Page">
    <jcr:content
        transportUri="http://localhost:4503/bin/receive?service=com.day.cq.replication.impl.transport.HttpTransportHandle"
        serializeAsXML="{Boolean}true"/>
</jcr:root>
java · after
@Component(service = TransportHandler.class)
public class LegacyTransport implements TransportHandler {
    // never invoked on AEM as a Cloud Service
}
