AEM-COMP-002 MissingResourceTypeComponent

Literal sling:resourceType or data-sly-resource type names no component under the project's /apps prefix.

ERROR · 15 min fix · Bug · Component compatibility

Literal sling:resourceType or data-sly-resource type names no component under the project's /apps prefix.

Why it matters

Content and templates bind to a resource type by string. When the component behind that string is renamed or moved, AEM resolves nothing at request time: the page renders blank, and neither javac nor the content-package build notices.

How to fix it

Point the reference at a component that exists under the project's /apps/<project>/ prefix, or restore the component directory. Search the content package for the old type after a rename so no author content is left behind.

xml · before
<sly data-sly-resource="${ @ resourceType='acme/components/elastic/metatagrenderer'}"/>

<!-- no directory at ui.apps/.../apps/acme/components/elastic/metatagrenderer -->
xml · after
<sly data-sly-resource="${ @ resourceType='acme/components/elasticsearch/metatagrenderer'}"/>
