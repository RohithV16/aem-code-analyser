AEM-COMP-001 DeprecatedClassicUiDialog

Component defines deprecated Classic UI dialog.xml instead of Granite UI _cq_dialog.

WARNING · 20 min fix · Code smell · Component compatibility

Component defines deprecated Classic UI dialog.xml instead of Granite UI _cq_dialog.

Why it matters

Classic UI dialog.xml is not read by the Touch UI editor, so authors cannot edit the component in AEM as a Cloud Service. It also drags in Classic UI client libraries that are not available there.

How to fix it

Migrate the dialog to a Granite UI _cq_dialog/.content.xml with sling:resourceType="cq/gui/components/authoring/dialog", then delete dialog.xml and check each field's xtype has a Granite equivalent.

text · before
acme/components/hero/dialog.xml
  <dialog jcr:primaryType="nt:unstructured">
    <items jcr:primaryType="nt:unstructured">
      <title jcr:primaryType="cq:Widget" xtype="textfield" fieldLabel="Title"/>
    </items>
  </dialog>
xml · after
acme/components/hero/_cq_dialog/.content.xml
  <jcr:root xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
            xmlns:cq="http://www.day.com/jcr/cq/1.0"
            jcr:primaryType="nt:unstructured"
            jcr:title="Hero"
            sling:resourceType="cq/gui/components/authoring/dialog">
    <content jcr:primaryType="nt:unstructured"
             sling:resourceType="granite/ui/components/coral/foundation/container">
      <items jcr:primaryType="nt:unstructured">
        <title jcr:primaryType="nt:unstructured"
               sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
               fieldLabel="Title"
               name="./title"/>
      </items>
    </content>
  </jcr:root>
